# Arisan Auto-Draw Scheduler

The auto-draw scheduler automatically triggers draws for pools when their `next_draw_timestamp` passes.

## How It Works

```
Vercel Cron (every minute)
         │
         ▼
/api/cron/draw (API Route)
         │
         ├─► Fetch all active pools with autoMode=true
         │
         ├─► Filter pools where next_draw_timestamp < now
         │
         └─► For each pool:
             ├─► Get eligible members (hasn't won, not kicked, not in default)
             ├─► Select random winner (crypto.getRandomValues)
             └─► Call execute_draw on-chain
```

## Files

| File | Purpose |
|------|---------|
| `src/lib/solana/scheduler.ts` | Core scheduler logic |
| `src/app/api/cron/draw/route.ts` | API endpoint for cron |
| `vercel.json` | Cron schedule configuration |

## Local Testing

### 1. Set Up Environment Variables

Add to `.env.local`:

```bash
# Your Solana RPC endpoint
NEXT_PUBLIC_SOLANA_RPC_URL=https://api.devnet.solana.com

# Scheduler wallet private key (base58 or JSON array)
SCHEDULER_PRIVATE_KEY=your_base58_private_key_here

# Secret for authenticating cron requests (any random string)
CRON_SECRET=local-test-secret-123
```

### 2. Create a Scheduler Wallet

Option A - Generate new keypair:
```bash
# Generate keypair
solana-keygen new -o scheduler-keypair.json --no-bip39-passphrase

# Get public key (fund this on devnet)
solana-keygen pubkey scheduler-keypair.json

# Fund on devnet
solana airdrop 1 $(solana-keygen pubkey scheduler-keypair.json) --url devnet

# Convert to base58 for env var
node -e "const fs=require('fs'); const bs58=require('bs58'); const key=JSON.parse(fs.readFileSync('scheduler-keypair.json')); console.log(bs58.default.encode(Buffer.from(key)))"
```

Option B - Use existing wallet:
```bash
# If you have a keypair file, convert to base58
node -e "const fs=require('fs'); const bs58=require('bs58'); const key=JSON.parse(fs.readFileSync('~/.config/solana/id.json')); console.log(bs58.default.encode(Buffer.from(key)))"
```

### 3. Start Development Server

```bash
npm run dev
```

### 4. Test the Endpoint

**Manual GET request (simulates Vercel cron):**
```bash
curl -X GET http://localhost:3000/api/cron/draw \
  -H "Authorization: Bearer local-test-secret-123"
```

**Manual POST request (for testing):**
```bash
curl -X POST http://localhost:3000/api/cron/draw \
  -H "Content-Type: application/json" \
  -d '{"secret": "local-test-secret-123"}'
```

### 6. Local Cron Simulation (Optional)

To simulate the cron running every minute locally:

```bash
# Using watch (runs every 60 seconds)
watch -n 60 'curl -s -X GET http://localhost:3000/api/cron/draw -H "Authorization: Bearer local-test-secret-123" | jq'

# Or create a simple script

    -H "Authorization: Bearer local-test-secret-123" | jq

done
```

## Production Deployment (Vercel)

### 1. Create Scheduler Wallet

```bash
# Generate a dedicated scheduler wallet
solana-keygen new -o scheduler-prod-keypair.json --no-bip39-passphrase

# Get public key
solana-keygen pubkey scheduler-prod-keypair.json

# Fund with SOL for transaction fees (0.1 SOL is plenty)
# On mainnet, send SOL to this address
# On devnet:
solana airdrop 1 $(solana-keygen pubkey scheduler-prod-keypair.json) --url devnet

# Export as base58
node -e "const fs=require('fs'); const bs58=require('bs58'); const key=JSON.parse(fs.readFileSync('scheduler-prod-keypair.json')); console.log(bs58.default.encode(Buffer.from(key)))"
```

### 2. Set Environment Variables in Vercel

Go to your Vercel project → Settings → Environment Variables

| Variable | Value | Environment |
|----------|-------|-------------|
| `NEXT_PUBLIC_SOLANA_RPC_URL` | Your RPC URL (Helius, QuickNode, etc.) | All |
| `SCHEDULER_PRIVATE_KEY` | Base58 encoded private key | Production |
| `CRON_SECRET` | Auto-generated by Vercel | Production |

> **Note:** Vercel automatically sets `CRON_SECRET` and sends it in the `Authorization` header for cron jobs.

### 3. Verify vercel.json

```json
{
  "$schema": "https://openapi.vercel.sh/vercel.json",
  "crons": [
    {
      "path": "/api/cron/draw",
      "schedule": "* * * * *"
    }
  ]
}
```

The schedule `* * * * *` means every minute. Other examples:
- `*/5 * * * *` - Every 5 minutes
- `0 * * * *` - Every hour
- `0 0 * * *` - Daily at midnight

### 4. Deploy

```bash
vercel --prod
```

### 5. Monitor Cron Jobs

- **Vercel Dashboard:** Project → Cron Jobs tab
- **Logs:** Project → Logs → Filter by `/api/cron/draw`

### 6. Verify It's Working

After deployment, check the Vercel logs for:
```

Found 1 pools ready for draw
```

## Troubleshooting

### "SCHEDULER_PRIVATE_KEY environment variable not set"
- Ensure the env var is set in Vercel
- Check it's available in the Production environment

### "Scheduler wallet balance is low!"
- Fund the scheduler wallet with more SOL
- Each draw costs ~0.000005 SOL

### "No eligible members for pool"
- All members may have already won
- Members may be in default or kicked

### "Unauthorized cron request"
- Verify CRON_SECRET matches in request header
- For local testing, ensure you're sending the correct Authorization header

### Draw not executing even though deadline passed
- Check pool has `autoMode: true`
- Check pool status is `active`
- Verify `next_draw_timestamp` is actually in the past

## Security Notes

1. **Scheduler Wallet Security**
   - Only store minimal SOL (for tx fees)
   - Never share the private key
   - Use a dedicated wallet, not your main wallet

2. **CRON_SECRET**
   - Prevents unauthorized triggers
   - Vercel manages this automatically in production

3. **Permissionless Draws**
   - The contract allows anyone to call `execute_draw` after the deadline
   - The scheduler just automates this process
