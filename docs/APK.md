# Android APK (CLOCK IN)

The APK is the Next.js app inside a **Solana Mobile web shell**: a native Android WebView app generated by `solana-mobile webshell init` (`android/`, package `com.arisan.clockin`). It is not a Bubblewrap/TWA build, because TWA breaks Mobile Wallet Adapter under Local Network Access.

The shell loads one URL, set at build time. Wallets connect through Mobile Wallet Adapter to whatever MWA wallet is installed (Seed Vault, Phantom, Solflare, or `fakewallet` for testing).

## Build

Requirements:
- JDK 17 or 21
- Android SDK with build-tools (`ANDROID_HOME`; the script defaults to `~/Library/Android/sdk`)
- Node

```bash
ARISAN_WEB_URL=https://<your-deployment> \
SOLANA_MOBILE_KEYSTORE_PASSWORD=<6+ chars> \
./scripts/build-apk.sh
# -> dist/arisan-clockin-<version>.apk  (signed release build)
```

`scripts/build-apk.sh` runs `npx solana-mobile@0.5.0 webshell build android` and then checks the result:
- It creates the signing keystore on first use at `ARISAN_KEYSTORE_PATH` (default `~/.config/arisan/arisan-clockin-release.jks`). **Back up the keystore and its password**: every update must be signed with the same key. Keystores are git-ignored.
- It accepts only `https://` URLs, or `http://localhost:<port>` for testing through `adb reverse`, because wallets and `crypto.subtle` need a secure context.
- It verifies the APK signature (`apksigner`), prints the package line (`aapt2`), and fails if `ARISAN_WEB_URL` isn't baked into the dex.

Optional variables:
- `ARISAN_VERSION_NAME` (default: `package.json` version)
- `ARISAN_VERSION_CODE` (default `1`; bump it for every update)
- `ARISAN_KEYSTORE_ALIAS` (default `arisan`)

## The deployed web app must match the deployed program

The APK only renders the web app. The web app's `NEXT_PUBLIC_SOLANA_RPC_URL` / `NEXT_PUBLIC_SOLANA_NETWORK` decide which cluster it talks to, and that cluster's program must match this repo's IDL.

**As of 2026-09-29, devnet still runs the pre-security program**:
- It was last deployed in slot 427830596.
- It has no `commit_draw_randomness`, and its Pool layout predates the security fix.
- Its upgrade authority is `CaJpp31WNCQAZPt11BY13Eqyu1vxPnnJYHDyhXmWwud6`.

Until someone with that key runs `anchor deploy` / `solana program deploy` of `main`, the app's IDL does not match devnet: draws cannot run, and new-layout pool reads can fail. The local-validator flow below works today.

## Run it on an emulator (tested)

This is the exact flow used for `docs/apk-proof/`: the current program on a local validator, the web app on the host, and the APK plus `fakewallet` on an emulator.

```bash
# 1. Program on a local validator (the .so is built from main)
(cd arisan_contracts/programs/arisan_contracts && cargo build-sbf)
solana-test-validator --reset --ledger /tmp/arisan-ledger \
  --bpf-program BjxGBSpEULzq9kJfx3bGB1rpVHwta8QuP2jeVKow3wN6 \
  arisan_contracts/target/deploy/arisan_contracts.so

# 2. Web app pointed at it
NEXT_PUBLIC_SOLANA_RPC_URL=http://localhost:8899 NEXT_PUBLIC_SOLANA_NETWORK=localnet npx next build
npx next start -H 127.0.0.1 -p 3107

# 3. Emulator (any API 28+ AVD), MWA test wallet, APK
~/Library/Android/sdk/emulator/emulator -avd <avd> -read-only &
npx solana-mobile@0.5.0 device install fakewallet
ARISAN_WEB_URL=http://localhost:3107/ SOLANA_MOBILE_KEYSTORE_PASSWORD=<test pw> \
  ARISAN_KEYSTORE_PATH=/tmp/test.jks ./scripts/build-apk.sh
adb install -r dist/arisan-clockin-0.1.0.apk
adb reverse tcp:3107 tcp:3107 && adb reverse tcp:8899 tcp:8899 && adb reverse tcp:8900 tcp:8900
adb shell am start -n com.arisan.clockin/.MainActivity

# 4. In fakewallet: GENERATE an account, then fund it on the local validator
solana airdrop 2 <fakewallet address> --url http://127.0.0.1:8899
```

Approve fakewallet prompts promptly. A signed transaction carries a recent blockhash, which is valid for about 60 s. Leaving the sign screen open longer fails with `BlockhashNotFound`.

## Production checklist
1. Deploy `main`'s program to the target cluster, using the upgrade authority.
2. Deploy the web app over **https** with that cluster's RPC URL.
3. Run `ARISAN_WEB_URL=https://… ./scripts/build-apk.sh` with the real release keystore.
4. Install on a Seeker or another Android device with a real MWA wallet, and repeat the create → invite → join check.
